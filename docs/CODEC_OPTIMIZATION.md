# 板端 AVI 转码优化 — 2026-10-09

用户授权范围：时间轴修复、JPEG 分块解码、内存检查。保持原分辨率、全部
帧、有理帧率和声音；保留一个 MP4，只有最终读回校验通过才删除原 AVI。
已有事件录像、AVI 右上角时间、照片和网络相关改动继续保留。

## 时间轴

此前直接将 AVI 的 `dwScale` 写为每帧 MP4 tick，并要求累计 tick 小于
`UINT32_MAX`。因此某些长片会在全部帧编码后返回 `mux_configuration_failed`。
当前先按最大公约数约分时间基；仍超出 32-bit 累计 tick 时，使用 version-1
`mdhd` 的 64-bit 时长。保持原视频的精确有理时钟，不丢帧、不舍入帧间隔。

64-bit 情形只流式复制并扩展 `moov` 元数据到文件尾，将旧 `moov` 标记为
`free`；不移动视频/音频载荷，不改变 `stco` 偏移，也不在内存中缓存整段
元数据。普通片段继续使用文件头的 `moov`。校验器支持两种媒体头，兼容
以前未约分的正常输出及其事务记录。

特殊测试 AVI 的 coprime 时间基为 `1000000001/1000000003`，只改本次拥有的
短测试文件头。它使少量帧的累计 tick 超出 32-bit，无需等待长片录制与转码。
旧版本实板结果：32/32 帧编码完成后 `mux_configuration_failed`，原 AVI 保留。

## 像素缓冲

JPEG 以 8/16 行分块输出 UYVY，逐块完成 full-range 到 limited-range 转换并
填入 I420。编码器直接读取 I420，不再分配内部 YUYV 到 I420 转换缓存。
取第一行色度的规则与固定版本编码器一致；保留已有黑位/色彩处理。

| VGA 像素缓冲 | 原路径 | 新路径 |
|---|---:|---:|
| JPEG 全帧 UYVY | 614400 字节 | 0 |
| 小块 UYVY | 0 | 最多 20480 字节 |
| I420 | 编码器内部 460800 字节 | 显式 460800 字节 |
| 合计 | 1075200 字节 | 481280 字节 |

上述缓冲差额是 **593920 字节 / 580 KiB**；不代表编码器全部内存占用。
H.264 输出缓冲、编码器工作区与 MP4 索引实现未更换。

## 内存检查

在相机 owner 暂停相机之后，检查内部空闲 RAM、PSRAM 总空闲量和最大连续
空闲块。自身缓冲预算包括最大 JPEG、I420、H.264 输出、JPEG 小块，并保留
256 KiB 余量；该检查不冒充完整的编码器/长片索引内存预算。
实际 codec 分配失败和组件内存错误也识别为资源不足。

资源不足返回 `psram_unavailable` 或 `internal_memory_unavailable`：队列
状态为 `paused`，清理本任务临时输出，保留 AVI，等待下次 idle 重试，不增加
实际失败计数、不触发连续三次失败保护。损坏源文件仍按真实失败处理。

## 保留边界

本轮未实现 MP4 索引落盘、编码器替换或跨抢占续转。长片仍可能因索引扩容、
SD 余量或其他资源问题暂停/失败；源 AVI/MP4 的 32-bit 文件大小边界仍保留。
短片和特殊时钟回归不等价于实际超十分钟或接近 4 GiB 文件的稳定性验收。
